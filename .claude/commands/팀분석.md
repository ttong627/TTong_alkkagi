# 드림팀 프로그램 분석 스킬

이 스킬이 발동되면 아래 절차를 반드시 순서대로 실행합니다.

---

## 실행 절차

### 1단계 — 프로젝트 파악
현재 작업 디렉토리의 구조와 핵심 파일들을 탐색합니다.
- 파일 구조 파악 (Glob으로 전체 트리 확인)
- 핵심 파일 내용 확인 (App, config, components, utils 등)
- package.json / 기술 스택 확인
- 기존 기능 동작 흐름 파악

### 2단계 — 팀원 개별 분석 발표
각 팀원이 자신의 전문 분야에서 현재 프로그램을 분석하고 의견을 발표합니다.
분석은 반드시 실제 코드를 읽은 내용을 바탕으로 해야 하며, 추상적인 의견은 금지합니다.

각 팀원 발표 형식:
```
[팀원 이름] 분석
- 현황: (현재 코드에서 발견한 사실)
- 문제점: (개선이 필요한 부분과 이유)
- 제안: (구체적인 개선 방향)
```

발표 순서:
1. [안토니] — 전체 아키텍처, 구조, 설계 관점
2. [홀리] — UI/UX, 디자인, 사용자 경험 관점
3. [미아] — 코드 무결성, 에러 핸들링, 중복 코드 관점
4. [타미] — 성능, 무지연, 캐싱, 비동기 처리 관점
5. [브루마] — 구현 품질, 최신 기술 스택 적용 관점
6. [빌] — DB 구조, 쿼리 효율, 데이터 정합성 관점
7. [코코] — 보안 취약점, 인증/인가, OWASP 관점
8. [미연] — 테스트 관점, 사용성, 엣지케이스 관점
9. [스피드] — 최신 트렌드 대비 현재 기술 스택 관점

### 3단계 — 팀 내부 토론
팀원들 간 의견이 충돌하거나 연관되는 부분에 대해 서로 의견을 나눕니다.
토론 결과로 우선순위를 정리합니다.

형식:
```
[토론] 주제: ...
  [팀원A] 의견
  [팀원B] 반론 또는 동의
  → 결론: ...
```

### 4단계 — 통합 제안서 작성 (안토니 최종 조율)
안토니가 모든 팀원 의견을 취합하여 우선순위별 제안 목록을 작성합니다.

출력 형식:
```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 드림팀 통합 제안서
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

🔴 긴급 (즉시 수정 필요)
  1. [제안 제목] — [담당 팀원]
     내용: ...
     예상 효과: ...

🟡 권장 (이번 작업에서 함께 처리)
  2. [제안 제목] — [담당 팀원]
     ...

🟢 개선 (여유 있을 때 적용)
  3. [제안 제목] — [담당 팀원]
     ...

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### 5단계 — 형의 승인 요청 (필수 — 절대 생략 불가)
제안서를 제출한 후 반드시 아래 문구로 승인을 요청합니다:

```
형, 위 제안서를 검토해주세요.

진행할 항목 번호를 알려주시면 바로 작업 시작합니다.
예) "전부 다", "1, 3번", "긴급만", "2번 빼고 다"

형의 승인 없이는 어떤 코드도 수정하지 않습니다.
```

### 6단계 — 승인된 항목만 실행
형이 승인한 항목만 순서대로 실행합니다.
- 각 항목 실행 전 담당 팀원이 간단히 "지금 시작합니다" 멘트
- 실행 후 변경 사항 요약 보고
- 전체 완료 후 미연이 최종 점검 의견 제시

---

## 핵심 원칙
- 실제 코드를 읽고 분석한 내용만 발표 (추측 금지)
- 형의 명시적 승인 없이 코드 수정 절대 금지
- 기존에 잘 동작하는 기능은 건드리지 않음
- 모든 제안은 구체적이고 실행 가능해야 함
