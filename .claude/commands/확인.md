# /확인 — 작업 준비 전방위 확인 (드림팀)

**발동**: 형이 "확인" 또는 "확인해"라고 하면 즉시. 세션 시작 시 자동 배너로도 안내된다.
**목적**: 프로젝트를 열자마자 **아무 지장 없이 바로 작업할 수 있는 상태인지** 한 번에 점검하고, 그 스냅샷을 **PROJECT_STATUS.md + 자동메모리에 항상 저장**한다.

## 절대 원칙 (위반 금지)
- **추측 금지**: 모든 항목은 실제 명령 실행 결과로만 보고한다.
- **날짜는 명령으로**: 타임스탬프·경과일은 `date`(또는 python)로 계산. 암산 금지.
- **동기화는 FF-only**: fast-forward 가능할 때만 자동 최신화. diverge·미커밋 변경 시 **절대 pull/​reset 하지 않고 경고만**.
- **시크릿 값 출력 금지**: .env 등은 **존재 여부만** 표시. 키/비밀번호 내용은 절대 출력하지 않는다(코코).
- **자동 push·배포 금지**: 확인만 한다. 빌드/커밋/푸시/배포는 **형의 별도 승인** 후에만(찰리·코코).
- **외과적**: 점검 과정에서 코드를 임의 수정하지 않는다(의존성 설치 제외).

## 실행 절차

### 1단계 — 프로젝트 식별 [빌]
```bash
git rev-parse --is-inside-work-tree 2>/dev/null || echo "NOT_GIT"
git remote get-url origin 2>/dev/null
git branch --show-current
```
- remote URL에서 **owner/repo** 추출 → GitHub 계정 후보.
- 배포/클라우드 ID 수집: `CLAUDE.md`, `AGENTS.md`, `.firebaserc`, `firebase.json`, `*deploy*.sh/.bat`, `vm-deploy.sh`, `T:\TTong_total\PROJECTS_INDEX.md`(있으면)를 읽어 **GCP project / Firebase project / 접속 URL / 호스팅(VM·Cloud Run·Hosting) / VM 인스턴스·존**을 추출한다.

### 2단계 — GitHub 계정 정합성 [코코]
```bash
gh auth status 2>&1 | grep -E "Active account|Logged in"
OWNER=$(git remote get-url origin | sed -E 's#.*github\.com[:/]([^/]+)/.*#\1#')
echo "repo owner: $OWNER"
```
- **멀티계정 PC 안전 원칙 — 전역 계정 전환 금지**: repo owner와 active 계정이 달라도 `gh auth switch`로 **전역 계정을 바꾸지 않는다**(다른 작업 세션·매시간 자동 pull 간섭 방지). 대신 owner 계정 토큰을 **그 git 명령에만** 주입한다:
  ```bash
  GHT=$(gh auth token --user "$OWNER" 2>/dev/null)   # owner 계정 토큰 확보(값은 절대 출력 금지)
  # 이후 모든 원격 git은 이 형태로 실행 → 전역 active 계정 불변:
  #   GH_TOKEN="$GHT" git -c credential.helper='!gh auth git-credential' <fetch|merge|pull|push> ...
  ```
  - `$GHT`가 비면 → owner 계정이 gh에 미로그인. **값 노출 없이** "gh auth login 필요(owner=$OWNER)"만 안내하고, active 계정 자격으로 폴백 fetch 시도.
  - owner == active 계정이면 주입 없이도 동작(주입해도 무해).
- 계정 세트 참고 (2026-07-19 정본 정리): **대부분 `ttong627` 정본** — 물류·웰쉐어 계열·Gemma4·cleancare·hanwool·wssc-*·tms-local-frontend·nexus-pipeline·auto_excel·logis-system·workspace-setup 등. **`ttong0627` 정본은 소수** — yyplus(영양플러스)·aipos·schedule_ttong·schedule_gg·wellshare-tms·tms-logistics-server·claude-config. (판단은 위 `OWNER` 자동감지가 우선; 이 목록은 참고용)

### 3단계 — 깃허브 FF-only 동기화 [안토니]
> 2단계에서 확보한 `$GHT`(owner 토큰)를 주입해 fetch/merge한다 — **전역 계정을 바꾸지 않는다**. (owner 미로그인이면 주입 없이 폴백)
```bash
GH_TOKEN="$GHT" git -c credential.helper='!gh auth git-credential' fetch origin 2>&1
git status -sb | head -3
git rev-list --left-right --count origin/$(git branch --show-current)...HEAD   # 왼쪽=behind, 오른쪽=ahead
```
판정:
- **behind>0 & ahead=0 & 워킹트리 clean** → `GH_TOKEN="$GHT" git -c credential.helper='!gh auth git-credential' merge --ff-only origin/<branch>` 실행(자동 최신화). 결과 보고.
- **ahead>0 / diverged / 미커밋·untracked 존재** → pull 보류, **경고만**. (로컬 작업 보호)
- behind=0 & ahead=0 → 이미 최신.

### 4단계 — 마지막 작업 파악 [도나]
```bash
git log -8 --pretty=format:"%h | %ad | %s" --date=format:"%Y-%m-%d %H:%M"
git show --stat --oneline HEAD | head -20
```
- 최근 작업 주제를 한 줄로 요약(무엇을, 어디 파일을).

### 4.5단계 — 규칙 문서(SSOT) 로드 [도나·안토니] ★모든 기능 사용의 열쇠
- **모든 메뉴·기능은 규칙 문서에 처리 방식이 기록되어 있다(형 지시 2026-07-05)** — 이 단계를 건너뛰면 기능을 절반만 쓰게 된다.
```bash
ls docs/*규칙*.md docs/*RULES*.md docs/*설계*.md docs/작업_핸드오프.md 2>/dev/null   # 규칙·설계 문서 스캔(모노레포면 각 앱 docs/)
```
- **읽는 순서**: ①`작업_핸드오프.md`(직전 세션·다음 작업) ②프로젝트 CLAUDE.md ③핵심 규칙 SSOT(예: yyplus=`보건소_고유규칙.md` 공통 절대규칙 ★0~10, `NUTRITION_PLUS_RULES.md`) ④이번 작업과 관련된 도메인 규칙만 정독(배송=`배송규칙.md`·`기사앱_규칙.md`·`배송순번_재설계.md`, 발주·집계=`발주집계_단일화_설계.md`, 메일=`메일수집_규칙.md`).
- 발견한 규칙 문서 목록을 **PROJECT_STATUS.md 「규칙 문서」 섹션에 박제**(다음 세션이 바로 찾도록). 자동메모리와 충돌하는 내용이 있으면 **문서(SSOT)가 우선** — 메모리를 갱신한다.

### 5단계 — 작업환경 점검 + 자동 정비 [베라·타미]
```bash
node -v; npm -v
command -v gh; command -v gcloud; command -v firebase   # 필요 도구 존재 여부
```
- **앱 디렉토리별 `node_modules` 존재 확인** → 없으면 해당 폴더에서 `npm install` **자동 실행**(표준 깊이). 실행한 곳을 보고.
- `.env`·`*.env`·시크릿 파일 **존재 여부만** 표시(값 금지).
- 빌드 스크립트(`package.json`의 scripts.build 등) 존재 확인. **실제 빌드는 기본 생략**(형이 "풀 점검" 요청 시에만 `npm run build` 실행).

### 6단계 — 배포 환경 [안토니]
- 문서 기반으로 다음을 정리: **접속 URL / 호스팅 / 배포 명령 / 빌드·커밋·푸시 흐름**.
- (선택) URL 1회 헬스체크: `curl -sS -o /dev/null -w "%{http_code}" <URL>` (타임아웃 5s, 실패해도 계속).

### 7단계 — 앱 구성 인벤토리 [빌·도나]
- 멀티앱/모노레포 스캔: 모든 `package.json`(node_modules 제외), `server/`·`functions/`·`desktop/`·`mobile/`·`scripts/` 등을 찾아 **각 앱의 이름·역할·기술스택**을 표로 정리.
```bash
git ls-files | grep -E "package\.json$" | grep -v node_modules
```

### 8단계 — 리스크 신호등 [찰리·코코]
- 미커밋/untracked 변경, 계정 불일치, 시크릿 누락, 의존성 미설치, 백업/워치독 미동작 등을 🟢/🟡/🔴로 표시.

### 9단계 — 저장 (항상·필수) [도나]
- **프로젝트 루트에 `PROJECT_STATUS.md`** 생성/갱신(아래 템플릿). 갱신시각은 `date '+%Y-%m-%d %H:%M %Z'` 결과를 사용.
- **자동메모리** 색인 `~/.claude/projects/<slug>/memory/MEMORY.md`에 `- [PROJECT_STATUS](...)` 포인터 1줄을 중복 없이 유지(없으면 추가). 메모리 본문은 PROJECT_STATUS.md를 단일 출처로 참조.

### 10단계 — 신호등 요약 출력
6블록(동기화 / 계정·식별 / 환경 / 배포 / 앱구성 / 마지막작업)을 🟢🟡🔴 한 화면으로 요약하고, 마지막에 **"다음 행동" 1줄**을 제시한다.
