# 드림팀 전체 점검 스킬

이 스킬이 발동되면 아래 절차를 반드시 순서대로 실행합니다.
목적: 현재 프로그램이 실제 배포해도 아무 문제가 없는 세계 최고 수준인지 전방위 점검.

---

## 실행 절차

### 1단계 — 전체 코드 정밀 탐색
점검에 앞서 프로젝트의 모든 파일을 실제로 열어서 읽습니다. 추측 금지.
- 전체 파일 구조 파악
- 진입점(App, index, main)부터 각 컴포넌트/모듈까지 순서대로 읽기
- 실행 흐름(Flow) 추적: 사용자 행동 → 이벤트 → 상태 변경 → 렌더링/응답 전 과정
- 환경설정 파일(config, .env, firebase, 라우터 등) 확인

### 2단계 — 팀원 개별 정밀 점검

각 팀원이 자신의 전문 분야에서 코드를 점검하고 발견한 문제를 보고합니다.
반드시 실제 파일명과 라인 단위로 지적해야 하며, 모호한 표현 금지.

발표 형식:
```
[팀원 이름] 점검 결과
✅ 이상 없음: (문제 없는 항목)
⚠️ 주의: (잠재적 문제, 파일명:위치 명시)
🚨 긴급: (즉시 수정 필요, 파일명:위치 명시)
```

점검 순서 및 각자의 체크리스트:

**[미아] — 코드 무결성 · 찌꺼기 점검**
- 사용하지 않는 import, 변수, 함수가 있는가
- 주석 처리된 채로 방치된 코드 블록이 있는가
- 중복 정의된 함수나 로직이 있는가
- TODO / FIXME / console.log 등 개발용 코드가 남아있는가
- 삭제했어야 할 잔여 코드(찌꺼기)가 있는가

**[타미] — 실행 단계별 로직 흐름 · 불필요 이벤트 점검**
- 사용자 시작 → 각 단계 전환이 매끄럽게 이어지는가
- 이벤트 리스너가 해제(cleanup) 되지 않고 누적되는 곳이 있는가
- useEffect / onAuthStateChanged / 구독(subscribe) 등 메모리 누수 가능성이 있는가
- 불필요한 리렌더링을 유발하는 상태 관리가 있는가
- 비동기 처리 중 race condition 가능성이 있는가
- 로딩 중 사용자가 다른 행동을 할 때 예외 처리가 되어 있는가

**[코코] — 보안 전방위 점검**
- API 키, 시크릿, 민감 정보가 클라이언트 코드에 노출되어 있는가
- Firebase Security Rules 또는 서버 측 권한 검증 없이 DB에 직접 접근하는가
- 사용자 입력값을 검증 없이 처리하는 곳이 있는가 (XSS, Injection 가능성)
- 인증 우회가 가능한 로직이 있는가 (authStatus 조작, URL 파라미터 남용 등)
- 관리자 기능이 클라이언트 조건만으로 보호되고 있지 않은가
- CORS, HTTPS, 환경변수 관리는 안전한가

**[빌] — DB 구조 · 데이터 정합성 점검**
- Firestore 읽기/쓰기가 불필요하게 과도하게 발생하는 곳이 있는가
- 존재하지 않을 수 있는 필드를 null 체크 없이 사용하는 곳이 있는가
- 데이터 업데이트 시 정합성이 깨질 수 있는 구조가 있는가
- increment, serverTimestamp 등 원자적 연산이 필요한 곳에 제대로 사용되고 있는가
- 인덱스 없이 복잡한 쿼리를 실행하는 곳이 있는가

**[브루마] — 성능 · 안정성 점검**
- 불필요하게 무거운 연산이 메인 스레드를 블로킹하는가
- 대용량 데이터를 페이지네이션 없이 한 번에 처리하는 곳이 있는가
- 에러 발생 시 앱이 죽거나 무한 로딩에 빠질 수 있는 곳이 있는가
- try-catch가 없는 비동기 처리가 있는가
- 의존성 배열이 잘못된 useEffect가 있는가

**[홀리] — UI/UX 안전성 점검**
- 로딩 상태가 없거나 잘못 처리된 화면이 있는가
- 에러 발생 시 사용자에게 아무 피드백도 없는 상황이 있는가
- 빈 데이터 / 엣지케이스에서 UI가 깨지는 곳이 있는가
- 접근성(키보드 탐색, 스크린리더 등) 문제가 있는가

**[안토니] — 전체 아키텍처 · 배포 준비 점검**
- 전체 모듈 간 의존성 구조에 순환 참조나 이상한 결합이 있는가
- 환경변수(.env)가 빌드에 올바르게 주입되는가
- 배포 시 빌드 에러를 유발할 수 있는 코드가 있는가
- 개발 환경에서만 동작하고 프로덕션에서 깨지는 로직이 있는가
- preview 파라미터처럼 배포 전 제거해야 할 임시 코드가 남아있는가

**[미연] — 사용자 시나리오 · 엣지케이스 점검**
- 신규 사용자 첫 진입 시나리오가 막힘 없이 동작하는가
- 네트워크 오류, 서버 지연 상황에서 앱이 안전하게 버티는가
- 동시에 여러 탭을 열거나 새로고침 시 이상 동작이 없는가
- 비정상적인 데이터(null, undefined, 빈 문자열, 매우 긴 문자열)가 들어올 때 안전한가

**[스피드] — 기술 부채 · 버전 점검**
- 현재 사용 중인 라이브러리 중 보안 취약점이 알려진 버전이 있는가
- deprecated된 API나 곧 지원 종료되는 기능을 사용하고 있는가
- 더 안전하고 효율적인 최신 방법으로 교체해야 할 코드 패턴이 있는가

### 3단계 — 팀 내부 교차 검토 및 토론
팀원들이 서로의 발견 사항을 공유하고 연관된 문제를 함께 논의합니다.
같은 문제를 여러 팀원이 지적한 경우 통합합니다.

형식:
```
[교차 검토] 주제: ...
  관련 팀원: ...
  종합 판단: ...
```

### 4단계 — 통합 점검 보고서 작성 (안토니 최종 정리)
모든 발견 사항을 취합하여 긴급 순위별로 정리합니다.

출력 형식:
```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
🔍 드림팀 전체 점검 보고서
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

📊 종합 평가: [배포 가능 / 조건부 배포 가능 / 배포 불가]

🚨 긴급 — 배포 전 반드시 수정
  1. [문제 제목] — 담당: [팀원]
     위치: 파일명 (대략적 위치)
     문제: ...
     해결책: ...

⚠️ 주의 — 이번에 함께 수정 권장
  2. [문제 제목] — 담당: [팀원]
     ...

📝 개선 — 다음 버전에서 처리 가능
  3. [문제 제목] — 담당: [팀원]
     ...

✅ 이상 없음
  - [정상 확인된 항목들]

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### 5단계 — 승인 요청 (절대 생략 불가)
보고서 제출 후 반드시 이 문구로 멈춥니다:

```
형, 점검 완료했습니다.

수정할 항목 번호를 알려주시면 바로 시작합니다.
예) "전부 다 고쳐", "긴급만 먼저", "1, 2번만", "보고서만 볼게"

형의 승인 없이는 코드 한 줄도 건드리지 않습니다.
```

### 6단계 — 승인된 항목 순서대로 실행
- 각 항목 시작 전 담당 팀원 멘트
- 수정 완료 후 변경 내용 간략 요약
- 전체 완료 후 미연이 최종 사용자 시나리오 재점검 의견 제시
- 배포 가능 여부 최종 판정

---

## 핵심 원칙
- 모든 지적은 실제 코드를 읽은 결과여야 함 (추측, 일반론 금지)
- 파일명과 위치를 반드시 명시
- 형의 명시적 승인 없이 코드 수정 절대 금지
- 정상 동작하는 기능은 건드리지 않음
- 문제 없는 항목은 "이상 없음"으로 명확히 표시
