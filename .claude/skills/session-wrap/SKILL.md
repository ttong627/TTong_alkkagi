# /session-wrap — 세션 마무리 (2026-09-27 다시 씀)

> 옛 판은 에이전트 5개를 띄우고 형에게 선택지를 물었다(지시문 파일 6개는 처음부터 없었다).
> 형 규칙 — 에이전트 최소·묻지 않고 끝까지 — 에 맞춰 **안토니가 직접** 아래 5개를 점검하고 바로 처리한다.
> 대화가 길어져 **다음 세션에 이어서** 해야 하면 `/핸드오프`(HANDOFF.md)를 먼저 쓴다. 이 스킬은 「끝내기 전 정리」다.

`--dry-run` 이면 점검만 하고 저장·커밋은 하지 않는다.

## 1. 발견 → 메모리 (가장 중요)

이번 대화에서 나온 것 중 **다음 세션이 몰라서 또 헤맬 것**만 저장한다.
- 형이 새로 정한 규칙·결정(형 원문 한 줄 인용), 되풀이될 함정, 실측으로 뒤집힌 사실
- 저장 전 같은 주제 메모리가 있는지 찾아 **있으면 그 파일을 고친다**(중복 금지). MEMORY.md 색인 줄도 같이
- ⛔코드·git 기록에 이미 있는 것, 이 대화에서만 의미 있는 것은 저장하지 않는다

## 2. 커밋 안 된 변경

```bash
git status --short; git log origin/HEAD..HEAD --oneline 2>/dev/null
```
- 이번 세션에 만든 변경이 남아 있으면 커밋한다(형 요청 범위 안에서). 운영 배포는 하지 않는다
- 다른 세션이 만든 변경은 건드리지 않고 보고만 한다

## 3. 낡은 문서

이번에 바꾼 기능이 PROJECT_STATUS.md·README·WORK_GUIDE.md·스킬 문서와 어긋나면 그 줄만 고친다.

## 4. 후속 할 일

이번 범위 밖이지만 해야 할 일은 `spawn_task` 칩으로 남긴다(설명은 한국어, 스스로 읽히게). 칩 도구가 없으면 보고서에 적는다.

## 5. 되풀이 작업 → 자동화 후보

같은 손작업을 이번 세션에서 3번 이상 했으면 스킬·스크립트 후보로 한 줄 적는다(만들지는 않는다).

## 보고 형식 (한국어·결론 먼저)

```
■ 마무리 결과: 메모리 N건 저장 · 커밋 N개 · 문서 N곳 · 후속 칩 N개
- 저장한 메모리: <파일> — <한 줄>
- 남긴 것(다른 세션 변경 등): …
■ 다음 행동: <한 줄>
```
