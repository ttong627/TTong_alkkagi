# SRT 화이트보드 애니메이션 (mask 연출 + stream 화법)

SRT 자막을 화이트보드 손그림 애니메이션으로 변환한다. **연출**은 영역별 마스크 리빌을 따른다(서사 순서대로 영역을 하나씩 드러내고, 시작 전 영역은 완전히 숨기며, 겹침은 `protectedRegions`로 보호). **화법**은 스트림 필적으로 바꾼다 — 각 영역은 자신의 허용 마스크 안에서 펜촉이 골격/그리드를 따라 연속적으로 미끄러지며 잉크를 얹고(기필 ink → 채색 color), 모든 영역은 하나의 지속 캔버스를 공유하며 이미 그린 영역은 캔버스에 남는다. 사용자에게 보여주는 모든 설명·분장(스토리보드)·설정·인터페이스 문구는 한국어를 사용해야 한다.

프레임 단위 점프나 사각형 지우기 방식과 다르게 이 스킬의 필적은 **연속적으로 흐른다**. 이미지 전체 stream 방식과도 다르게 이 스킬은 **자막의 서사 영역** 단위로 순서대로 그림을 그려, 각 요소의 등장 순서와 타이밍을 제어할 수 있다.

## 기본 구현 파라미터

| 항목 | 기본 요구사항 |
|---|---|
| 종이 배경 | 생성 이미지는 따뜻한 미색 낡은 종이색(권장 `#F5EBD7`) 사용. 렌더링 시 원본 이미지의 네 모서리 안쪽에서 샘플링해 바탕을 물들이며, 순백색 금지. |
| 화법 | 영역마다 stream 연속 필적: 기필 `ink`(선화 깔기) → 채색 `color`(원색 복원). 가중치 `ink:color = 2:1`. |
| 필적 경로 | `--ink-path grid`(그리드, 기본, 안정적) 또는 `skeleton`(골격 추적, 선화가 뚜렷한 일러스트에 더 밀착). |
| 채색 스타일 | `--color-fill contour-wipe`(윤곽 스캔, 기본) 또는 `brush`(궤적을 따라 브러시). |
| 미작화 영역 | 영역의 허용 마스크 = 사각형 `region`에서 「이후 영역 + protectedRegions」를 제외한 부분. 시작 전 영역은 완전히 숨김. |
| 시간 길이 출처 | 각 이미지의 `sceneDurationMs`는 해당 장면 자막의 시간 범위에서 온다(장면당 25–35초 권장). |
| 편집 박스 | 미리보기 편집대는 기본적으로 모든 번호 편집 박스를 표시. 편집 박스는 애니메이션 화면 내용이 아님. |

## 통일된 이미지 생성 시각 규범 (필수)

모든 장면의 원본 이미지는 동일한 시각 언어를 따라야 한다. 생성 전 아래 요구사항을 이미지 생성 프롬프트에 완전히 포함하고, 생성 후 항목별로 검사한다:

- **스타일과 구도:** 미니멀 손그림 일러스트, 순수 스케치 드로잉 스타일, Notion풍의 절제된 두들 미학. 개념 표현이 중심이며 사실성을 추구하지 않는다. 구도는 간결하게, 배경은 깨끗하게, 여백을 충분히 두고, 전체적으로 차분하고 명료한 정서를 유지하며, 시리즈 내에서 선/인물/배색을 일관되게 한다.
- **색상과 재질:** 미색 종이 배경 `#F5EBD7`, 짙은 회색 스케치 선. 빨강·주황·파랑만 소량의 개념적 포인트 색으로 허용. 그 외의 강조색, 고채도 배색, 복잡한 텍스처는 사용 금지.
- **인물과 오브젝트:** 오브젝트는 간결한 윤곽, 최소한의 선, 여백으로 표현한다. 실제 비례·재질·디테일이 아니라 관계/변화/핵심 개념을 강조한다.
- **절대 금지:** 장면 원본 이미지 안의 모든 문자, 단어, 알파벳, 숫자, 글꼴, 라벨. 사실적 표현, 사진적 디테일, 3D 효과, 회화 질감. 복잡한 장면, 밀집된 배경, 번잡한 장식, 고채도 화면.
- **그리는 손 예외:** `drawing-hand.png` 펜대에는 한글 문구('미래이음연구소')가 있다. 이는 그리는 손 오버레이의 일부일 뿐 장면 원본 이미지의 문자가 아니므로 지우거나 다시 그릴 필요가 없다. 사용자가 자신의 로고·문구로 교체를 원하면 `scripts/set_pen_text.py`로 펜대 문구만 바꿔 준다.

## 확인 관문 (필수)

기본 워크플로의 **각 단계가 완료될 때마다 반드시 멈추고 사용자의 명시적 확인을 기다린 후**에 다음 단계를 시작할 수 있다. 확인 전에는 다음 단계의 이미지·주석·미리보기·영상·병합 파일을 생성해서는 안 된다. "무응답", "이전의 포괄적 승인", "사용자가 반대하지 않음"을 확인으로 간주해서는 안 된다. 사용자가 이전 단계의 수정을 요청하면 해당 단계만 다시 수행하고, 완료 후 다시 확인을 기다린다.

유일한 연계 동작: **주석 JSON 생성이 완료되면 즉시 자동으로 미리보기 편집대를 열고 해당 JSON이 있는 디렉터리를 로드해야 한다.** 이는 3단계의 산출물에 속하므로 "미리보기 편집대 열기"에 대해 별도의 확인을 기다릴 필요가 없다. 브라우저의 File System Access API가 사용자 제스처를 요구하면 브라우저 인터페이스로 이미 정해진 그 디렉터리를 선택한다. 이를 이유로 사용자에게 추가 확인을 요구하거나 사용자가 직접 미리보기 편집대를 열도록 바꿔서는 안 된다.

## 워크플로

1. **자막 읽기, 전략 제시 (이미지 생성 없음).** `scripts/parse_srt.py`로 SRT를 자막 항목으로 파싱하고 장면당 25–35초 기준으로 권장 분장(스토리보드)을 산출한다. 이를 바탕으로 삽화 전략을 제시한다: 각 장면의 번호, 핵심 표현, 화면 주체, 대응 자막 구간과 `sceneDurationMs`. 각 장면은 하나의 핵심 의미만 표현한다. **완료 후 멈추고 사용자의 전략 확인을 기다린다.**
2. **선화 생성.** 사용자가 전략을 확인한 후에만, "통일된 이미지 생성 시각 규범"에 따라 장면별로 16:9 따뜻한 미색 낡은 종이 배경의 선화 이미지를 생성한다. 배경은 `#F5EBD7`, 주체 사이에 자동 분할이 쉽도록 충분한 여백을 남긴다. 문자, 복잡한 사진, 겹치는 오브젝트, 규범과 충돌하는 요소를 생성해서는 안 된다. **완료 후 멈추고 선화를 보여준 뒤 사용자 확인을 기다린다.**
3. **자막을 먼저 읽고 이미지를 본 다음, 주석을 만들고 미리보기 편집대를 연다.** 사용자가 선화를 확인한 후에만, 먼저 해당 이미지에 대응하는 자막을 읽고, 실제로 이미지를 확인하고, 원본 이미지의 픽셀 크기를 얻는다. 자막만으로 화면을 추측하거나 화면 위치만으로 기계적으로 순서를 매겨서는 안 된다. 자막의 서사 이벤트를 먼저 추출한 뒤, 이미지의 가시적 주체를 이벤트에 대응시키고, "장면 깔기 → 핵심 인물/사물 → 행동·갈등·변화 → 반응/결과"의 의미 순서로 그리기 순서를 배치한다. 그 후 `<이미지명>.annotation.json`을 생성한다. 생성이 완료되면 즉시 기본 브라우저로 `assets/preview.html`을 열고, 미리보기 편집대의 "폴더 열기"로 **해당 주석 파일이 있는 디렉터리**의 모든 `<이름>.png` + `<이름>.annotation.json`을 로드한다. 파일 경로만 알려주거나 사용자에게 직접 조작을 요구해서는 안 된다. **미리보기 편집대에 디렉터리가 로드된 후 멈추고, 주석과 미리보기 내용에 대한 사용자 확인을 기다린다.**
4. **영역 미리보기 이미지 생성.** 사용자가 주석과 미리보기 내용을 확인한 후에만, `render_annotation_preview.py`로 번호/방향 검사 이미지를 만들고, 영역 분할과 서사 순서의 일치, 영역이 모두 캔버스 안에 있는지, 겹치는 주체가 `protectedRegions`로 보호되는지 대조한다. **완료 후 멈추고 사용자의 미리보기 이미지 확인을 기다린다.**
5. **미리보기 편집대에서 조정하고 저장.** 사용자가 미리보기 이미지를 확인한 후에만, 이미 열려 있고 해당 디렉터리가 로드된 미리보기 편집대에서 조정한다: 기본(재생 전)에는 전체 이미지와 영역 박스를 표시. 캔버스는 **사각형 프록시**다: 영역의 네 변·네 모서리를 드래그해 `region`을 수정하고, 우측에서 이름/방향/**시작(ms)/종료(ms)**(길이 = 종료−시작, 읽기 전용)과 **자막**을 수정하며, 모듈 목록을 드래그해 **순서를 조정**(자동으로 `sequence` 재배열)하고, 모듈을 선택하면 대응 자막이 자동 하이라이트된다. 타임라인을 드래그하거나 재생을 눌러 리빌을 확인한다(시작 전 영역은 표시되지 않음). `direction`은 이 프록시에만 영향을 준다. 수정 후 "이 장면 저장/전체 저장"을 눌러 원본 `.annotation.json`에 기록한다(각 영역의 `subtitle` 포함, `sceneDurationMs`는 마지막 영역 종료+0.5초에 맞춤). **저장 후 멈추고 최종 주석과 타이밍에 대한 사용자 확인을 기다린다.**
6. **커맨드라인으로 최종 영상 렌더링.** 사용자가 최종 주석과 타이밍을 확인한 후에만, `render_stream_whiteboard.py`로 장면별 고화질 MP4를 만들고, 오프닝·임의의 겹치는 모듈 중간·엔딩 세 시점을 표본 검사한다. 사용자가 자막 표시를 원하면 렌더링 직후 `burn_subtitles.py`로 해당 장면 SRT를 번인한 결과를 완성본으로 삼는다. **완료 후 멈추고 사용자의 완성본 확인을 기다린다.**
7. **다중 장면 병합 (다중 장면일 때만).** 사용자가 모든 단일 장면 완성본을 확인한 후에만, `merge_scenes.py`로 순서대로 하나로 병합한다. **완료 후 멈추고 최종 합성 영상에 대한 사용자 확인을 기다린다.**

## 디렉터리 규칙

사용자 프로젝트 안에 생성:

```text
assets/whiteboard/<프로젝트명>/
  scene-01-<이름>.png
  scene-01-<이름>.annotation.json     # png와 동일한 이름
  scene-01-<이름>-whiteboard.mp4      # 완성본
  scene-01-<이름>-preview.mp4         # 실제 클립(미리보기 편집대 생성, 저화질)
```

이미지와 설정은 반드시 같은 이름이어야 한다: `foo.png` ↔ `foo.annotation.json`. 미리보기 편집대는 이를 기준으로 설정을 자동 로드한다.

## 의미 기반 순서와 픽셀 단위 주석 (반드시 수행)

1. **읽기 근거:** 주석 전에 자막과 실제로 확인한 원본 이미지가 모두 있어야 한다. 하나라도 없으면 먼저 요청하고, 주석을 생성해서는 안 된다.
2. **순서 근거:** `sequence`, `startMs`, `label`은 자막 속 이벤트의 선후를 반영해야 하며, 단순히 왼쪽→오른쪽, 위→아래 또는 시각적 두드러짐 순이어서는 안 된다.
3. **좌표 근거:** 각 모듈은 원본 이미지 좌표계의 정수 픽셀 `x`, `y`, `width`, `height`를 출력한다. 원점은 좌측 상단이며, 백분율/비율/추정 좌표나 크기 생략은 금지. `canvas.width`/`canvas.height`는 원본 이미지 픽셀 크기와 같아야 한다.
4. **모듈 필드:** 각 요소는 `sequence`, `narrativeRole`, `subtitle`, `region`, `reveal`, `handPath`를 포함한다. `narrativeRole`은 자막 속 서사적 역할을 한국어로 설명하고, `subtitle`은 그 영역에 대응하는 자막 텍스트(SRT에서 옴, 미리보기 편집대 연동과 후속 용도)를 저장하며, `sequence`는 1부터 연속.
5. **검증:** 미리보기 생성 전에 각 영역이 캔버스 안에 있는지, 대응하는 가시적 주체를 덮는지, 자막 이벤트와 부합하는지 검사한다. 겹치는 주체는 `protectedRegions`로 보호한 후 모듈을 그린다.

## 타이밍 모델 (stream 화법 전용)

- **장면별 총 길이** `sceneDurationMs`는 해당 장면 자막의 시간 범위에서 온다(`parse_srt.py`의 `scenes[].sceneDurationMs`).
- **영역 직렬 작화:** stream 화법은 펜 하나가 움직이는 것이므로, 같은 장면 안의 각 영역은 **시간상 순차적으로 진행**해야 한다(`startMs` 비중첩): 다음 영역은 이전 영역의 `startMs + durationMs`(+ 선택적 100–300ms 호흡)에서 시작한다. `startMs`가 겹치면 렌더러는 순서대로 처리하지만, 시각적으로 더 이상 동시 진행이 아니다.
- **영역 내 ink→color:** 각 영역의 `durationMs`는 `ink:color = 2:1`로 기필 구간과 채색 구간으로 나뉜다. `durationMs`는 미리보기 편집대의 **시작/종료 시간**으로 결정되며(종료−시작), 그 영역에 대응하는 자막 길이에 맞출 수 있다. 초기 추정으로 150픽셀/초 × 그리기 거리를 쓸 수도 있다.
- **응시 마무리:** 모든 영역을 다 그린 후 자동으로 `sceneDurationMs`까지 채우며, 마지막에 최소 0.5초 동안 완전한 원본 이미지가 유지되도록 보장한다.
- `reveal.direction`은 stream 화법에서 **실제 필적을 결정하지 않는다**(필적은 골격/그리드에서 자동 생성). 미리보기 편집대의 사각형 프록시 시연 용도로만 쓰이며, 편집대 사용성을 위해 유지된다.

## 마스크 불변식 (연출 계층, 반드시 수행)

- 시각 `t`에 모듈은 자신의 `reveal.startMs ≤ t` 이후이면서 현재 작화 진행도를 넘지 않는 픽셀만 표시할 수 있다. 시작 전 모듈의 어떤 선/채움/이미지도 나타나서는 안 된다.
- 각 영역의 **허용 마스크** = 사각형 `region`에서 모든 **후속 모듈의 `region`**을 제외하고, 다시 이 모듈의 `reveal.protectedRegions`를 제외한 것. stream 잉크는 허용 마스크 안으로 제한되므로 후속 영역의 선이 미리 드러나지 않는다.
- `protectedRegions`는 `region`과 같은 원본 이미지 정수 픽셀 좌표를 사용하며, 사각형이 너무 크거나 주체가 겹치거나 배경 선이 새어 나올 수 있는 경우에 쓴다.
- 렌더러는 "허용 마스크 안으로 잉크 제한 → 후속 영역과 보호 영역은 자연히 건드리지 않음" 순서를 이미 구현했다. 미리보기 편집대의 사각형 프록시는 동등한 `destination-out` 제외로 같은 연출을 시연한다.

## 설정 예시

```json
{
  "sceneId": "scene-01",
  "canvas": { "width": 1672, "height": 941 },
  "storyBasis": "이 장면 자막의 이벤트 요약",
  "sceneDurationMs": 9000,
  "elements": [
    {
      "id": "rockery",
      "label": "바위산 장면",
      "sequence": 1,
      "narrativeRole": "이야기의 장면 깔기",
      "subtitle": "원숭이 산 위, 새끼 원숭이 한 마리가 바위산 꼭대기에 앉아 바나나를 들고 있다.",
      "type": "structure",
      "region": { "x": 20, "y": 120, "width": 540, "height": 780 },
      "reveal": { "direction": "top_to_bottom", "startMs": 300, "durationMs": 2600, "maskPaddingPx": 22, "protectedRegions": [] },
      "handPath": { "start": [290, 130], "end": [290, 890], "easing": "easeInOut" }
    }
  ]
}
```

> `direction` / `handPath`는 미리보기 편집대의 사각형 프록시 전용이다. 완성본의 필적은 stream이 자동 생성하므로 정밀 조정이 필요 없다.

## 스크립트 사용

모든 렌더링 스크립트는 스킬 내 `.venv` 인터프리터로 실행한다(의존성 격리).

1. **환경 준비** (최초 또는 의존성 누락 시):
   ```bash
   python scripts/prepare_env.py --check   # 탐지; 성공 시 마지막 줄에 ENV_PY=<경로> 출력, 캡처해 둘 것
   python scripts/prepare_env.py           # 없으면 .venv 생성 후 opencv-python/numpy/av 설치
   ```
2. **자막 파싱 + 권장 분장**:
   ```bash
   python scripts/parse_srt.py <자막.srt> --target-sec 30 --min-sec 25 --max-sec 35
   ```
3. **영역 번호 미리보기 이미지**:
   ```bash
   python scripts/render_annotation_preview.py <이미지> <주석> <미리보기_출력>
   ```
4. **미리보기 편집대 (서버 불필요)**: Chrome / Edge로 `assets/preview.html`을 직접 열고, "폴더 열기"로 디렉터리 선택 → 모든 이미지+동일 이름 주석 로드 → 드래그 편집 → "저장"으로 원본 파일에 기록. 기록에는 File System Access API가 필요(Chrome/Edge). 다른 브라우저는 다운로드 후 수동으로 덮어쓴다. 렌더링은 여전히 커맨드라인으로 한다(아래 5단계).
5. **단일 장면 렌더링**:
   ```bash
   <ENV_PY> scripts/render_stream_whiteboard.py <이미지> <주석> <출력mp4> assets/drawing-hand.png \
       [--ink-path grid|skeleton] [--color-fill contour-wipe|brush] [--total-ms <밀리초>]
   ```
   `--total-ms` 생략 시 주석의 `sceneDurationMs`를 사용. 마지막 줄에 `OUTPUT=<경로>` 출력.
6. **다중 장면 병합**:
   ```bash
   <ENV_PY> scripts/merge_scenes.py --inputs 장면1.mp4 장면2.mp4 장면3.mp4 --output final.mp4
   ```
7. **자막 번인 (선택, 시스템 ffmpeg 필요)**: 자막을 화면에 새겨 넣어 어떤 플레이어에서든 보이게 한다.
   ```bash
   <ENV_PY> scripts/burn_subtitles.py <영상.mp4> <자막.srt> <출력.mp4> [--font-size 21] [--margin 26]
   ```
8. **GIF 변환 (선택)**: README·미리보기용 경량 GIF.
   ```bash
   <ENV_PY> scripts/mp4_to_gif.py <영상.mp4> <출력.gif> [--width 640] [--fps 8]
   ```
9. **펜대 문구 교체 (선택)**: 빈 펜(assets/drawing-hand-blank.png)에 원하는 문구를 합성한다.
   ```bash
   <ENV_PY> scripts/set_pen_text.py "원하는 문구" [--out assets/drawing-hand.png]
   ```
10. **TTS 내레이션 합성 (선택, 네트워크 필요)**: 자막을 한국어 신경망 음성으로 읽어 영상에 입힌다. 완성 영상은 기본적으로 무음이므로, 소리가 필요하면 이 단계를 거친다.
   ```bash
   <ENV_PY> scripts/add_narration.py <영상.mp4> <자막.srt> <출력.mp4> [--voice ko-KR-InJoonNeural] [--fit]
   ```

## 품질 검사

렌더링 전/후 확인:

- 첫 프레임이 깨끗한 따뜻한 미색 낡은 종이 배경이며, 선이 미리 드러나지 않는다.
- 대응 자막을 읽고 원본 이미지를 실제로 확인했다. `canvas`가 원본 이미지 픽셀 크기와 일치하고, 모든 `region`이 정수 픽셀 좌표이며 캔버스 안에 있다.
- `sequence`, `startMs`가 자막 이벤트 순서와 일치한다. 미리보기 이미지의 번호/라벨/영역이 같은 주석 JSON에서 나왔다.
- 오프닝, 임의의 겹치는 모듈 중간, 모든 모듈 완료 후 세 시점에서 검사: 미작화 모듈이 보이지 않고, 겹침 보호 영역이 새어 나오지 않으며, 마지막 프레임에 완전한 원본 이미지가 표시된다.
- 펜촉이 진행 중인 필적에 밀착해 있다. 선화가 뚜렷한 일러스트는 `--ink-path skeleton`으로 필적을 더 밀착시킬 수 있다.
- 모든 모듈 종료 후 최소 0.5초 동안 완전한 원본 이미지가 유지된다.
- 다중 장면 병합 후 순서·길이가 자막 분장과 일치한다.

효과를 수정하려면 먼저 미리보기 편집대(`assets/preview.html`)에서 주석(영역/순서/타이밍)을 조정하고 저장한 뒤 커맨드라인으로 렌더링한다. 무작정 반복해서 영상을 뽑지 않는다.
