# 시험판 설치·업데이트

휴대폰에 시험판을 **한 번만 설치**하고, 그 뒤로는 새 판을 받을 때마다 **지우지 않고 업데이트**로 깐다.

## 안드로이드가 업데이트를 허락하는 조건
1. 앱 ID 가 같다: `TTong.alkkagi`
2. **서명 키가 같다** — 시험판은 늘 업로드 키(인증서 SHA-256 `90:DB:EE:10…8A:B0`)로 서명한다.
3. **빌드 번호(versionCode)가 더 크다** — CI 실행 번호로 자동으로 늘어난다.

빌드 115·119·122 는 CI 가 매번 새로 만드는 임시(디버그) 키로 서명돼 있어 서로 업데이트가 안 됐다. 그 판이 깔려 있으면 **한 번만** 지우고 새 시험판을 깐다. 그 뒤로는 업데이트만 하면 된다.

## 자동 업데이트 (2026-10-11 형 요청)

시험판(sideload)은 **켤 때마다** 새 판이 있는지 확인하고, 있으면 스스로 내려받아 업데이트한다.

1. 첫 화면을 열면 `version.json`(아래 고정 링크 옆)의 빌드 번호와 지금 빌드 번호를 비교한다.
2. 새것이면 위쪽에 「새 판(빌드 N) 받는 중 37%」가 뜨고, 다 받으면 설치한다. 설치가 끝나면 앱이 닫힌다 — 다시 열면 새 판이다.
3. **처음 한 번만** 「이 출처 허용」(출처를 알 수 없는 앱 설치)을 켜야 한다. 앱이 「허용하러 가기」 단추를 보여 준다.
4. 안드로이드 12 이상은 그 뒤로 **누를 것 없이** 설치된다. 근거: 공식 문서 `PackageInstaller.SessionParams#setRequireUserAction` — 자기 자신을 업데이트하고, `UPDATE_PACKAGES_WITHOUT_USER_ACTION` 을 선언하고, 대상 SDK 가 기준 이상이면 사용자 동작이 필요 없다(이 앱은 SDK 36). 안드로이드 11 이하는 「설치」를 한 번 누른다.
5. 실제 확인: `updater-e2e` 워크플로가 안드로이드 14 에뮬레이터에서 빌드 1 을 켜고, 손대지 않고 빌드 2 로 바뀌는지 본다.

- 스토어 판(play)에는 이 기능과 인터넷 권한이 없다(플레이 정책: 스토어 앱은 스토어로만 업데이트). CI 가 두 판을 따로 만들고 권한을 검사한다.
- 인터넷이 안 되면 조용히 넘어가고 다음에 켤 때 다시 본다.

## 늘 최신 판 고정 링크 (자동)

**https://github.com/ttong627/TTong_alkkagi/releases/download/test-latest/tanji-murim-test.apk**

- main 에 바뀐 것이 들어갈 때마다 CI 가 휴대폰(arm64) 시험판을 빌드해 이 링크의 파일을 바꾼다. 링크는 그대로다.
- 올리기 전에 서명 인증서가 업로드 키(`90:DB:EE:10…8A:B0`)인지 `apksigner` 로 확인한다. 아니면 올리지 않는다(다른 키 파일이 올라가면 휴대폰 업데이트가 막히기 때문).
- 텔레그램으로 「빌드 N · 바뀐 점 · 링크」를 보낸다.
- 저장소가 비공개면 이 링크는 깃허브에 로그인해야 받아진다.

### 처음 한 번 저장소 비밀값 등록 (형)
깃허브 → 저장소 Settings → Secrets and variables → Actions → New repository secret

| 이름 | 값 |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | `upload.jks.base64` 파일 내용 |
| `ANDROID_KEYSTORE_PASSWORD` | `secrets.txt` 의 같은 이름 값 |
| `ANDROID_KEY_ALIAS` | `upload` |
| `ANDROID_KEY_PASSWORD` | `secrets.txt` 의 같은 이름 값 |
| `TELEGRAM_BOT_TOKEN` | `D:\Gemma4\telegram_config.json` 의 `bot_token` |
| `TELEGRAM_CHAT_ID` | 받을 대화 번호(형 개인 대화) |

- 위 네 개(키)가 없으면 고정 링크 단계는 건너뛴다. 텔레그램 두 개가 없으면 알림만 건너뛴다.
- 키를 등록하면 CI 가 처음부터 업로드 키로 서명하므로 아래 「만드는 법」의 손 서명은 필요 없다.

## 판 확인
첫 화면 맨 아래에 `v0.1.0 · 빌드 N` 이 보인다. 새로 받은 판의 빌드 번호가 더 크면 업데이트된다.

## 어떤 파일을 쓰나
| 파일 | 용도 | versionCode |
|---|---|---|
| `tanji-murim-N-arm64.apk` (시험판·자동 업데이트, 업로드 키 서명) | **휴대폰 시험판(늘 이것)** | 2000 + N |
| `tanji-murim-N.apk` | 스토어 판과 같은 모든 기기용(업데이트 기능 없음) | N |
| `tanji-murim-N.aab` (업로드 키로 다시 서명) | 플레이 콘솔 올리기 | N |

- 시험판은 **arm64 전용만** 쓴다. versionCode 가 2000 대라 모든 기기용(100 대)을 그 위에 깔면 "낮은 판"이라 거절된다.
- 플레이 스토어에서 받은 앱은 구글이 다른 키(앱 서명 키)로 서명한다. 시험판과 서로 업데이트되지 않으므로, 스토어 판으로 바꿀 때 한 번 지운다.

## 만드는 법 (작업 환경)
1. 깃허브 Actions `app` 을 `make_release` 켜고 실행 → 릴리스 `build-N` 에 파일이 올라간다.
2. arm64 APK 를 받아 업로드 키로 다시 서명:
   ```bash
   export ALKKAGI_KEYSTORE_PASSWORD=… ALKKAGI_KEY_PASSWORD=… ALKKAGI_KEY_ALIAS=upload
   tools/signing/sign-apk.sh upload.jks tanji-murim-N-arm64.apk 탄지무림-N.apk
   ```
   - 서명 도구 apksig 2.3.0 을 Maven Central 에서 받아 SHA-1 을 대조한다. v2 서명만 한다(앱 최소 안드로이드 7).
   - 서명 뒤 검증 결과와 인증서 지문, 압축하지 않은 항목의 정렬(네이티브 라이브러리 16KB)을 확인한다.
3. 플레이용 AAB: `tools/signing/sign-aab.sh upload.jks tanji-murim-N.aab out.aab --no-symbols`

키 파일·비밀번호는 저장소에 없다(`.gitignore` 로 막음). 저장소 비밀값 4개를 등록하면 CI 가 처음부터 업로드 키로 서명하므로 2·3 단계가 필요 없다(체크리스트 O-03).
